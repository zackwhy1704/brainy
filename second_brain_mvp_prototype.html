End-to-end MVP technical specification

Product scope

  • Capture via Share Sheet / Android share intent.
  • URL, text, image, screenshot, PDF and voice ingestion.
  • AI Brief: summary, entities, topics, tasks, decisions, importance.
  • Automatic project/topic assignment.
  • Semantic Ask over personal memory.
  • Evidence-backed insights and source links.
  • Calendar/task actions first; broader MCP later.

Android flagship

  • Kotlin + Jetpack Compose.
  • Hilt + Coroutines + Room.
  • Share Intent for primary ingestion.
  • Optional foreground overlay/floating bubble with explicit permission.
  • MediaProjection only for explicit screen capture workflows.
  • Gemini Nano/AICore where device/API availability supports it.
  • FCM for background sync and insight notifications.

iOS

  • Swift + SwiftUI.
  • Share Extension for URLs, text, images and files.
  • App Intents for actions and Siri/Shortcuts integration.
  • WidgetKit for “What changed?” and open loops.
  • Foundation Models where supported for local summarization/extraction.
  • BackgroundTasks for bounded background processing.
  • No assumption of arbitrary cross-app screen access or floating overlay.

Backend

  • API: Kotlin/Ktor or TypeScript/NestJS.
  • PostgreSQL as system of record.
  • pgvector for semantic retrieval in MVP.
  • Redis for queues/cache/rate limits.
  • S3-compatible object storage for files/audio.
  • Worker service for ingestion → extraction → embedding → memory updates.
  • LLM gateway supporting cloud models plus platform-local results.

Core data model

  • User
  • Source / Capture
  • Content / Chunk
  • Entity
  • Topic
  • Project
  • Insight
  • Decision
  • Task
  • Event
  • Embedding
  • Agent Action / Tool Call

Privacy architecture

  • Encrypt data in transit and at rest.
  • Device-local processing whenever practical.
  • Explicit consent before cloud processing.
  • Per-source delete/export.
  • Keep raw content separate from derived memory.
  • Audit every external action.
  • Never design around covert scraping of other apps.

Processing pipeline

Capture ↓ Normalize (URL/text/image/audio/PDF) ↓ Content extraction / OCR / transcription ↓ AI extraction ├── summary ├── entities ├── topics ├── tasks ├── decisions ├── claims └── importance ↓ Embedding + entity resolution ↓ Memory linker ├── existing project? ├── existing person? ├── related sources? ├── contradiction? └── new insight? ↓ PostgreSQL + pgvector ↓ Retrieval / RAG ↓ Agent ├── answer ├── create task ├── calendar event └── notify user

Suggested MVP stack

Mobile

Android: Kotlin, Compose, Hilt, Coroutines, Room, Retrofit/OkHttp

iOS: Swift, SwiftUI, App Intents, Share Extension, WidgetKit, Foundation Models

Backend

Kotlin/Ktor if maximizing reuse of existing Kotlin expertise; otherwise TypeScript/NestJS. PostgreSQL + pgvector, Redis, S3-compatible storage, Docker.

AI

On-device: Apple Foundation Models / Gemini Nano when available.
Cloud: model gateway with structured JSON outputs. Use smaller models for extraction and larger models only for synthesis/reasoning.

Deployment

Start with one cloud region, managed PostgreSQL, managed Redis, object storage and containerized API/worker services. Avoid Kubernetes until scale requires it. Add observability from day one.

MVP boundary

Build: capture, AI brief, automatic organization, semantic memory, Ask, evidence, projects, tasks and calendar actions, Android floating experience, iOS Share/App Intents.

Do not build yet: direct WhatsApp/WeChat/Telegram scraping, autonomous control of arbitrary apps, full MCP marketplace, enterprise Slack connectors, always-on recording, custom foundation model, full knowledge graph UI, multi-agent orchestration.

North-star test: after 30 days, a user should be able to capture something from any app, forget about it, and later ask the Second Brain a question whose answer depends on that captured information plus their accumulated context.
